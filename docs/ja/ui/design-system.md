# Design System

## 1. 目的

本書は、Virtual Vessel Studioの全画面が共通して使用する見た目の定義（Design Tokens）を定める（方式設計14.4、14.34）。

各画面・各Componentは、本書で定義した値のみを使用する。画面ごとに独自の色、文字サイズ、余白を定義しない。

見た目の基準は、次の見本ページで確認できる。

```text
docs/assets/ui/styleboard.html
```

ブラウザで直接開くと、パレット、ダーク／ライト、日本語／英語、色の見え方を切り替えて確認できる。本書と見本ページは常に一致させる。どちらかを変更した場合は、もう一方も同じ変更で更新する。

関連文書：

- `components.md`：共通Componentの仕様
- `ui-guidelines.md`：画面を作るときのルール

---

## 2. デザインの方向性

- VTuber向けのApplicationとして、やわらかく、かわいい印象を持たせる。
- かわいさは、**丸みのある形**と**淡いアクセント色**で表現する。文字の大きさや余白は落ち着かせ、配信中でも読みやすく保つ。
- 既定は紫からピンクの配色（Lavender）とし、利用者が複数のパレットから選択できる。
- 背景は暗い色を基本（ダーク）とし、明るい背景（ライト）にも切り替えられる。
- 色の見え方や身体的な条件に関わらず使えることを、かわいさより優先する（9章）。

## 3. 色

### 3.1 構成

色は次の3種類で構成する。

| 種類 | 内容 | パレットによる変化 |
|---|---|---|
| アクセント | Primary、Secondary | パレットごとに変わる |
| ニュートラル | 背景、面、枠線、文字 | パレットの色相（Hue）をごくわずかに混ぜる |
| 状態 | 成功、注意、エラー、配信中 | パレットに関わらず固定 |

状態の色をパレットに連動させない理由は、どのパレットでも「緑系は成功、赤系はエラー」という意味を保つためである。

### 3.2 パレット

| パレット | 色相（H） | Primary | Secondary |
|---|---|---|---|
| Lavender（既定） | 268 | `#c3a6ff` | `#ff9ccf` |
| Sakura | 335 | `#ffa3c4` | `#c9a8ff` |
| Mint | 165 | `#34e8b8` | `#6cc4ff` |
| Sky | 212 | `#6bb5ff` | `#c7b2ff` |
| Peach | 18 | `#ff8a5c` | `#ffc04d` |
| Lemon | 48 | `#ffd23f` | `#ff9ec4` |

- 表の値は基準値である。表示するときは背景に合わせて調整する（HSLで計算）。ダークでは明度を6%上げて明るく、ライトでは彩度を25%上げ、明度を12%下げて濃くする。淡い背景の上でも色が見えるようにするためである。
- どちらも淡い色であり、その上に置く文字は常に`On Accent`（濃い色）とする。
- パレットを追加する場合は、Primaryの上で`On Accent`が4.5:1以上になることを確認する。

### 3.3 ニュートラル

ニュートラルは、パレットの色相Hを使ってHSLで定義する。彩度は低く抑え、背景や面は無彩色に近い色とする。背景に色を混ぜすぎると画面全体が濁って見えるためである。パレットの色は、背景ではなくアクセントと装飾（3.6）で見せる。

| Token | 用途 | ダーク（S / L） | ライト（S / L） |
|---|---|---|---|
| Background | 画面全体の背景 | 8% / 8% | 20% / 97% |
| Surface | 画面・パネル | 7% / 12% | 10% / 99% |
| Surface 2 | カード、入力の背景 | 6% / 16% | 15% / 95% |
| Surface 3 | 押せる面、トラック | 6% / 21% | 14% / 91% |
| Border | 枠線、区切り線 | 6% / 26% | 10% / 86% |
| Text | 本文 | 15% / 95% | 12% / 16% |
| Text 2 | 補足、ラベル | 5% / 74% | 8% / 34% |
| Text 3 | 注記、メタ情報 | 4% / 62% | 6% / 40% |
| Disabled | 無効な部品の文字・つまみ | 3% / 40% | 4% / 72% |
| On Accent | アクセント色の上の文字 | 45% / 14% | 45% / 14% |
| Accent Line | 細い線、小さなアクセント文字 | Primaryと同じ | 58% / 38% |

例：Lavenderのダークの`Background`は`hsl(268, 8%, 8%)`となる。

`Accent Line`は、選択中の枠、タブの下線、ナビゲーションの選択表示、スライダーの塗り、小さな見出し文字に使う。ライトでは淡いPrimaryが背景と区別しにくいため、濃い色調に切り替える。

### 3.4 状態

| Token | 意味 | ダーク | ライト | 形（9.1） |
|---|---|---|---|---|
| Success | 成功、接続済み、良好 | `#1affcc` | `#006652` | ✓ |
| Warning | 注意、不安定 | `#ffb31a` | `#7a5200` | △（中に !） |
| Error | 失敗、見つからない | `#ff8a9d` | `#b2001e` | × |
| Live | 配信中 | `#ff85b1` | `#ad0040` | ●（塗りつぶし） |
| （なし） | 停止中、未接続 | Text 2 | Text 2 | ○（輪郭） |

- Successは、Errorとの区別がつきやすいよう、緑ではなく青緑寄りとする。
- 状態は、色だけでなく必ず形と文字を一緒に表示する（9.1）。

### 3.5 派生色

| Token | 定義 | 用途 |
|---|---|---|
| Glow | Primaryの不透明度35% | Primary Buttonやトグルの光彩 |
| Tint | SurfaceにPrimaryを14%混ぜた色 | ナビゲーションの選択背景 |
| 状態の淡い背景 | 状態色の不透明度18% | 状態表示（Chip）の背景 |
| 状態の枠 | 状態色の不透明度65% | 状態表示（Chip）の枠 |
| 状態の面 | 状態の淡い背景をSurface 2に重ねた不透明の色 | 状態表示（Chip）の背景。背景の帯の上でも読みやすさが変わらない |
| Primary Wash / Secondary Wash | Primary、Secondaryの不透明度28%（ダーク）、24%（ライト） | Cardのタイトル部分の背景（3.6） |

### 3.6 アクセントの装飾

背景を無彩色に近づけた分、パレットの色は次の装飾で見せる。華やかさを出しつつ、うるさくならない範囲にとどめる。

| 場所 | 装飾 |
|---|---|
| Card | 上端に3pxの線（Primary）。タイトルの左に幅4px・高さ16px・角丸2pxの縦バー（線と同じ色）。タイトル部分の背景に`Primary Wash` |
| 並んだCard | 1枚おきに、線・バーをSecondary、背景を`Secondary Wash`に替える |
| 画面のヘッダー | 下端に2pxの線。PrimaryからSecondaryへの横方向のグラデーションとする |

- グラデーションは、PrimaryからSecondaryへの2色だけとし、細い線や小さな飾りに限る。本文や操作部品の背景には使わない。
- 装飾の線、バー、Washは飾りであり、意味を持たせない。状態や選択は、これまでどおり形・文字・`Accent Line`で表す。
- Washの上の見出しはTextで書き、4.5:1以上になることを自動テストで確認する（9.2）。見出しの右端に置く状態表示（Chip）は不透明の背景（状態の面）を持つため、帯の上でも読みやすさは変わらない。
- 帯は見出しの背景として敷き、見出しの中身（Chip等）に合わせて高さが伸びるようにする。
- 「動きを減らす」の設定に関わらず、装飾は動かさない。

## 4. 文字

### 4.1 Font

| 用途 | Font | License |
|---|---|---|
| UI全般 | Noto Sans JP | SIL Open Font License 1.1 |
| 数値、ログ、識別子 | Noto Sans Mono | SIL Open Font License 1.1 |

- UI要素へFontを個別に指定しない。Typography Styleを通して使う（方式設計14.8）。
- 将来の言語追加に備え、Fallback Fontを設定できる構成とする（方式設計14.9）。

### 4.2 Typography Style

| Style | サイズ / 太さ | 行間 | 用途 |
|---|---|---|---|
| Heading | 22px / 700 | 1.3 | 画面の見出し |
| Subhead | 16px / 700 | 1.4 | セクション、設定項目名 |
| Body | 14px / 400 | 1.6 | 本文、ラベル |
| Caption | 12px / 400 | 1.5 | 補足、注記 |
| Button | 13px / 700 | 1.0 | ボタン |
| Numeric | 20px / 600、Mono | 1.2 | 数値の表示（等幅数字） |
| Monospace | 12px / 400、Mono | 1.5 | ログ、識別子 |

- 12pxより小さい文字は使わない。
- 列に並ぶ数値は等幅数字にする。

## 5. 余白

| Token | 値 | 主な用途 |
|---|---|---|
| XS | 4px | アイコンと文字の間 |
| S | 8px | 同じグループ内の部品の間 |
| M | 16px | カードの内側、カード同士の間 |
| L | 24px | 画面の内側、セクションの間 |
| XL | 40px | 大きなまとまりの間 |

余白はこの5段階からのみ選ぶ。

## 6. 形

| Token | 値 | 用途 |
|---|---|---|
| Radius S | 8px | 入力欄、状態表示、小さな部品 |
| Radius Control | 10px | ボタン、切り替えボタン（Segmented） |
| Radius M | 14px | カード、ナビゲーション項目、お知らせ |
| Radius L | 22px | 画面、ダイアログ |
| Radius Round | 高さの半分 | トグル、丸いアイコンボタン |
| Border | 1px | 通常の枠線 |
| Border（エラー） | 2px | エラー状態の入力欄 |

ボタンや状態表示は角丸四角形、トグルとアイコンボタンは丸とする。角の丸みと淡いアクセント色が、見た目の印象の中心である。

Unity UI Toolkitでは、角丸の半径が要素の高さの半分を超えると楕円に描かれる。そのため、`999px`のような大きな値は使わない。丸い部品（Radius Round）は、半径を高さのちょうど半分に指定する。

---

## 7. 動き

- 状態の切り替え（ホバー、トグル）は0.12〜0.15秒程度の短い変化とする。
- 常に動く表現は、配信中を示す表示の点滅など、意味のあるものに限る。
- OSの「視覚効果を減らす」設定が有効な場合は、点滅や移動を止める。

## 8. Theme

利用者が選べる見た目の設定は次の3つとする。いずれもUI固有設定として保存する（方式設計14.38）。

| 設定 | 選択肢 | 既定 |
|---|---|---|
| パレット | Lavender、Sakura、Mint、Sky、Peach、Lemon | Lavender |
| 背景 | ダーク、ライト | ダーク |
| UIの拡大縮小 | 実装時に段階を決める | 100% |

## 9. だれにでも使いやすく

### 9.1 状態は色だけで伝えない

- 状態には3.4の形のアイコンと文字を必ず付ける。
- 色の見え方が人によって違っても区別できることを、見本ページの「色の見え方」切り替え（赤緑、青黄、白黒）で確認する。この切り替えは開発時の確認用であり、Applicationの画面には含めない。

### 9.2 読みやすさ

全パレット・両背景でこの基準を満たすことを、Unity側の自動テスト（`ThemeTokenTests`）で確認する。状態表示の文字は、その状態の淡い背景をカードの上に重ねた色に対して4.5:1以上とする。

- 本文と背景のコントラストは4.5:1以上、大きな文字、アイコン、部品の境界は3:1以上とする。
- アクセント色の上の文字は`On Accent`とする。

### 9.3 操作しやすさ

- 押せる部品は24px以上の大きさとする。
- すべての操作をキーボードで行えるようにし、選択中の部品には必ず枠を表示する。
- 説明（ツールチップ）は、マウスのホバーだけでなくキーボードで選択したときにも表示する。

### 9.4 設定への追従

- UIの拡大縮小、パレット、ダーク／ライト、動きを減らす設定に追従する。
- 拡大しても文字が切れないよう、幅は固定せず中身に合わせる（方式設計14.7）。

## 10. Unityでの実装方針

詳細はUI基盤の詳細設計で定める。本書の範囲では次を前提とする。

- Tokenの値は`unity/VirtualVesselStudio/Assets/VirtualVessel/UI/Theme/design-tokens.json`に置く。本書を変更したら、このファイルも同じ値にする。
- TokenはUSSのCustom Property（`--vv-color-primary`、`--vv-space-m`、`--vv-radius-control`等）として定義し、各ComponentのUSSは`var()`で参照する。
- USSは`color-mix()`やHSLの計算に対応しない。そのため、ニュートラルと派生色はパレット・背景の組み合わせごとに計算済みの値を生成する（UI基盤詳細設計7.1）。
- Fontは、FontSetごとに生成したUSSが指定する（UI基盤詳細設計7.2）。
- USSには行間（line-height）の指定がない。4.2の行間は見本ページ（ブラウザ）での値であり、Unityでは各Fontの既定の行間となる。

---

## 11. 変更手順

1. 本書と`docs/en/ui/design-system.md`を更新する。
2. `docs/assets/ui/styleboard.html`を同じ内容に更新する。
3. `design-tokens.json`を更新し、Unityで「Virtual Vessel > UI > Generate Theme」を実行する。
4. `ThemeTokenTests`を実行し、コントラスト比と見本ページとの一致を確認する。
5. ダーク、ライト、日本語、英語、色の見え方の各表示で確認する。
