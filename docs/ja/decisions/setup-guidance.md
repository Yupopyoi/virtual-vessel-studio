# 初めての人への案内：決定と経緯

初めて使う人に、設定をどう案内するか（方式設計14.32）。初回の案内の画面を作らず、設定の画面のヘルプで説明する理由。

## 2026-11-22：初回の案内の画面を作らず、設定の画面のヘルプで説明する（方式設計14.32）

**きっかけ：** 設計書にあって作っていない機能を洗い出したとき、初めて起動したときの案内（方式設計14.32）が残っていた。利用者は、案内が必要だと考え、設計を頼んだ。

**作った設計の案：** 画面全体を覆う層に、ようこそ、6つの段階（アバター、カメラ、マイク、ゲーム画面、声、配信）、完了の面を順に出す。各段階には、設定の画面と同じCardを出す。最初の面でスキップでき、途中で閉じられ、あとから設定の画面で開き直せる。声は「あとで」とし、Voice Labの作業には入らない。画面案も作った。

**決定（利用者、2026-11-22）：** 案内の画面は作らない。設定の画面の各行のヘルプ（`components.md` 3.28）で、しっかり説明する。

**理由：** 画面案を見て、わざわざここまでの説明は要らないと利用者が判断した。設定の画面は、ページとCardで項目が分かれていて、各行のヘルプで説明すれば足りる。

**案内の案から残すもの：**

- 「サンプルのアバターを使う」：アプリに付属のサンプルのモデルを、ファイルを選ばずに登録するボタン。アバターのCardに置く（`docs/ja/ui/screens/setup.md` 5章）。

**再び検討するとき：** データフォルダーの変更とプロジェクトの選択ができ、最初に選ぶことが増えたとき。案の全文は、この記録を足したブランチの作業の中で捨てたため、残っていない。上の要点から作り直す。
