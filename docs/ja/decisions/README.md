# 決定記録

設計がなぜ今の形なのか。詳細設計（`docs/ja/detailed-design/`）には今の動作とその値を書き、それぞれの決定に至った経緯はここに残す。詳細設計を読みやすく保ち、経緯も失わないためである（開発の進め方11.2）。

## ここに書くこと

- 試したこと、利用者が見たこと（報告や動画）、計測したこと。
- 比べた方法と、外した方法、その理由。
- それぞれの決定の日付と、誰の決定か。

## 書き方

- 分野ごとに1つの記録とする（例：`avatar-motion.md`）。説明する詳細設計の節から、ここへリンクする。
- 新しい決定は、その記録の最後に、日付と説明する節を見出しにして足す。前の記録は書き換えない。
- ほかの文書と同じく、日本語と英語を合わせて保つ（`docs/en/decisions/`）。
